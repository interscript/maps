= BGN/PCGN coverage status (corrected 2026-10-28)

This page previously conflated three different things: whether a map
exists, whether a model exists, and whether training data exists. The
corrected status is below. The full reference inventory is
`README.adoc` in this directory.

== Held vs encoded

55 held documents = 53 language systems + 1 policy document + 1
duplicate. The corpus has 55 `bgnpcgn-*` maps across 41 language
codes (37 non-Roman-script language systems plus 4 Roman-script
convention systems).

== Correction of the earlier "BLOCKED" list

The earlier version of this page declared five systems "permanently
BLOCKED" — Burmese, Dzongkha, Inuktitut, Lao, Shan — because no
training data exists. Two errors:

1. **Dzongkha was not a gap.** Its encoding is in open PR #166.
2. **The blocked status applies to the model, not the map.** Every one
   of these systems has a held, complete deterministic table with its
   own example rows. A map can be encoded and verified without a
   training corpus; only a neural model needs one.

The same page claimed the nine reverted systems were
"abugida/abjad-adjacent systems where the table alone is
insufficient". That is false: eight are Cyrillic alphabets and one
(Modern Syriac) is an abjad with a complete table. They were merged
and CI-gated; the revert was a regression, and the maps are to be
restored, not re-encoded.

== Model layer (the real data block)

No gold romanization/transliteration pairs exist in the data supply
for: Burmese, Dzongkha, Inuktitut, Lao, Shan.

[cols="1,2,1",options="header"]
|===
|Language |Available data |Usable for model training

|Burmese |OCR, text segmentation, translation pairs |No — no romanization gold
|Dzongkha |None |No
|Inuktitut |None |No
|Lao |Raw text corpus |No — no romanization gold
|Shan |None |No
|===

Policy: withhold a model rather than ship a bad-quality one. This
blocks training, not map coverage. The maps for these languages are
in scope for encoding.
