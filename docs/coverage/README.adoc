= Reference-to-corpus inventory: what exists, what is recoverable, what is a gap

:toc:
:toclevels: 3

Status date: 2026-10-28.

This document is the authority-by-authority answer to one question:
**for every reference document the project holds, what is the state of
its encoding, and what is genuinely missing?** It supersedes the A1
workboard. The corpus on `main` is the authority for what is encoded;
this document records where every held source document stands against
it.

== Status vocabulary

[cols="1,3",options="header"]
|===
|Status |Meaning

|ENCODED
|A verified `.isc` exists on `main` (CI gates: ISC parse, embedded
tests, cross-runtime parity).

|RECOVERABLE
|The encoding exists in git history or on a merged/PR branch, but is
not on `main`. Restore or land it; do not re-encode from the PDF.

|OPEN PR
|A contributor PR carries an encoding in the legacy `.imp` format.
Migrate to `.isc`, verify, and land.

|SOURCE HELD, NOT ENCODED
|The authority document is held and no encoding exists anywhere. This
is a real encoding gap.

|SOURCE NOT HELD
|The corpus has an encoding (verified) but the project does not hold
the source document. An archival/verification gap, not an encoding
gap.

|DATA-BLOCKED (model layer only)
|No gold parallel data exists for training a neural model. The
deterministic map may still be encodable; this status applies to the
ML layer, never to the map.
|===

==== The Chinese annex is not a Han-character romanizer

Annex D states its scope explicitly: it applies to personal names
**already rendered in Hanyu Pinyin** and standardises that rendering
(surname title case, no umlauted `ü`, spacing, apostrophes). It
assumes the pinyin form; it does not supply a Han → pinyin lexicon.
Its three appendices are:

* Appendix A — the IC transliteration table (pinyin inventory);
* Appendix B — conversion tables from Wade-Giles, Yale and Mandarin
  Phonetic to pinyin;
* Appendix C — a list of common Chinese surnames.

Consequences for encoding:

* an `odni-zho-Latn-Latn` normalisation map (pinyin in, IC style out)
  is encodable from the annex;
* the Appendix B conversion tables are encodable as Latn→Latn maps;
* a Han → pinyin map (`odni-zho-Hans-Latn`) is **out of scope of this
  document** — it needs a character lexicon, not a rule table. The
  corpus already has `bgnpcgn-zho-Hans-Latn-1979` (Hanyu Pinyin) for
  that need.

==== The Kurdish annex

Annex G is a Perso-Arabic (Sorani) → Latin table for personal names,
using the 26 Latin letters plus the apostrophe, deliberately without
diacritics. It is a full table and is encodable as
`odni-kur-Arab-Latn-2011`. The corpus's `bgnpcgn-kur-Arab-Latn-2007`
is a different authority and does not substitute for it.

=== AUTOROM (BGN automated romanization package)

`32-BGN-10.5-Geographic Names Automated Romanization Script` (the BGN
conference paper), the `Romanize.py` implementation, the Hanyu
Pinyinizer workbook, and per-language data (`arm_data.py`, ...).

This is not a romanization standard and owes no map. It is a

differentially tested.

=== BGN 1964 and USBGN 1994 historical editions

`BGN_Romanization_Guide_1964` (16 documents) and
`USBGN_Romanization_1994` (30 documents) hold the historical editions
of the same systems. They are the source documents for the systems
whose current BGN/PCGN sheet is also held — including Hebrew 1962,
Burmese 1970, Khmer 1972 and Lao 1966. They do not create new gaps;
they make the four historical systems encodable.

=== ALA-LC

The official catalogue of 78 romanization tables is captured
(`alalc-roman.html`); the diff is in `alalc-diff.txt` (30 tables
encoded, 47 catalog systems not encoded).

**Availability gap:** the project holds only one table document,
`alalc/1997/mongolia.pdf`. The 55 ALA-LC maps on `main` are verified
corpus entries, but their source tables are not archived here.
Encoding any of the 47 catalog gaps requires acquiring the table
documents first. Several ALA-LC gaps overlap languages we already
encode under other authorities (Burmese, Khmer, Lao, Shan, Hebrew,
Pashto, Thai, Urdu, Uyghur, Uzbek, Kurdish), which lowers their
priority: a new authority is only worth encoding when a consumer needs
that authority's output, not merely the script conversion.

=== ICAO

Held: 9303 Part 3 (Amd 1) and the 9303 Arabic helper. The corpus has
8 `icao-*` maps. The held Part 3 was verified **not** to contain the
language transliteration tables (they live in another 9303 part or
edition) — a documented capture finding, not an encoding gap.

== Recoverable work (do not re-encode)

* The nine PR #208 maps were restored in PR #211. Do not re-encode
  them from the PDFs.
* Migrate PR #166 (`bgnpcgn-dzo-Tibt-Latn-2010.imp`) and PR #167
  (`bgnpcgn-syr-Syrc-Latn-2011.imp`) from `.imp` to `.isc`, verify the
  embedded tests, and land them. Resolve the language code: the ISO
  639-3 code for Classical Syriac is `syc`; Modern Syriac/Assyrian is
  `aii`/`syr`. The BGN document is Modern Syriac — pick the code with
  evidence, not by analogy.

== Model layer (separate from map coverage)

The deterministic map and the neural model are independent products.
A language can have a map and no model; that is the normal state for
most of the corpus.

Model-covered romanization/diacritization today: Hebrew, Khmer, Thai,
Persian, Arabic, Urdu (see `interscript-models/models.yaml`).

**DATA-BLOCKED models** — no gold romanization/transliteration pairs
exist in the data supply: Burmese, Dzongkha, Inuktitut, Lao, Shan.
This blocks *training*, not encoding. Policy: withhold a model rather
than ship a bad-quality one.

== Why the earlier workboard was wrong

The A1 workboard diffed a catalogue of held PDFs against the corpus
files on `main` and concluded that 17 BGN/PCGN systems were missing.
Three facts were not checked:

1. **Merged history.** Nine of the systems had already been merged in
   PR #208. A later revert removed them; the workboard then counted
  them as gaps again.
2. **Open PRs.** Dzongkha and Modern Syriac were already encoded in
   open contributor PRs #166 and #167.
3. **Authority overlap.** Hebrew was covered by an ICAO map; Khmer by
   a shipped model; Thai had just landed in PR #204.

The correct method — used in this document — is: check `main`, check
open PRs, check merged history, check other authority prefixes, and
only then call a system missing. The corpus is the authority for what
is encoded; a PDF diff alone never is.
